# ---------------------------------------------------------------------------
# ACAS - Applewood Computers Accounting System
# COBOL -> Python 3.12 migration of the batch posting cycle
#
# requirements.txt - the flat, exactly pinned dependency list.
#
# WHAT THIS FILE IS
#   The dependency set of the Python re-implementation of the ACAS batch
#   posting cycle: transaction validation, the batch-control-total gate,
#   posting to the General, Sales, Purchase and IRS ledgers, and the
#   period-total and control-account updates.
#
#   It carries the SAME pins as pyproject.toml in flat form, for environments
#   without a build backend:  pip install -r requirements.txt
#
#   pyproject.toml is the AUTHORITATIVE manifest - it declares the
#   interpreter floor and ceiling, the packaging rules and the test-runner
#   configuration. This file mirrors its pins and must never drift from them;
#   a mismatch between the two manifests is a defect.
#
#   See README-python-migration.md for how to build the comparison oracle,
#   seed a scenario, run both cycles and diff the resulting table state.
#
# WHAT THIS FILE IS NOT
#   It is not a manifest for the COBOL system. The COBOL tree (common/,
#   copybooks/, general/, sales/, purchase/, irs/, stock/), the generated
#   MySQL bridge (common/*MT.scb, common/*MT.cbl) and the schema
#   (mysql/ACASDB.sql) are FROZEN specification sources: read exhaustively,
#   never modified. The compiled comparison oracle under harness/ needs a
#   container toolchain - GnuCOBOL 3.2, MariaDB 10.11.7, MariaDB
#   Connector/C 3.3.4, the JC preSQL translator - and those versions are
#   declared in harness/Dockerfile.*. They must never appear here.
#
# TARGET RUNTIME
#   CPython 3.12.3. Its decimal module is backed by the C libmpdec 2.5.1
#   implementation rather than the pure-Python fallback, which matters for
#   both correctness and speed, because every monetary and quantity
#   operation in the migrated cycle passes through decimal.Decimal.
#
# HOW TO READ THE PIN LINES
#   Every non-comment line is exactly  name==version . No ranges, no extras,
#   no environment markers, no URLs, no hashes. The versions were resolved
#   on the build host, not recalled. Do not upgrade, downgrade or "check for
#   newer": a driver or runtime change can move a stored penny, and the only
#   acceptable proof of equivalence is an empty scenario diff against the
#   compiled COBOL oracle.
# ---------------------------------------------------------------------------

# ---------------------------------------------------------------------------
# DELIBERATELY EXCLUDED
#
# This block is a CONTRACT, not a note. Every package named below is absent
# because a binding rule forbids it - not because it was overlooked. Adding
# any of them breaks that rule, and the breakage would not announce itself
# as a failing test: it would surface as a wrong figure in a posted ledger.
#
#   pandas, numpy, and any other array / dataframe / statistics package
#       Zero binary floating point in accounting computation. No accounting
#       value may pass through a binary float at any point - not in
#       computation, not in storage, not in transport. The exclusion is
#       ABSOLUTE and extends to the harness dump comparison, which uses
#       ordered row sequences rather than dataframes. Corroboration from the
#       frozen schema: mysql/ACASDB.sql declares ZERO FLOAT, DOUBLE and REAL
#       columns - its numeric census is 167 DECIMAL, 151 INT, 116 TINYINT,
#       23 MEDIUMINT, 22 SMALLINT and 3 BIGINT - so no binary float can
#       enter from the database side either.
#
#   any ORM entity layer - the SQLAlchemy ORM, Django ORM, peewee, tortoise,
#   pony, SQLModel and every equivalent
#       Plain modules and dataclasses only; SQLAlchemy is permitted at Core
#       level and no further. An ORM would want to own schema definition,
#       which the schema freeze prohibits, and would impose identity-map and
#       flush-ordering semantics the COBOL does not have, obscuring the exact
#       statement ordering that the state diff is sensitive to.
#
#   alembic, and any other schema-migration tool - yoyo-migrations,
#   sqlalchemy-migrate, django and every equivalent
#       mysql/ACASDB.sql is frozen and no DDL is ever emitted: no tables, no
#       columns, no indexes, no constraints, no views, no triggers. A
#       migration tool has nothing legitimate to do here, and its presence
#       would invite schema drift.
#
#   any asyncio, threading or connection-pool helper - aiomysql, asyncmy,
#   anyio, trio, gevent, eventlet, the sqlalchemy asyncio extra, and every
#   pool manager
#       Execution is strictly sequential, matching the single-threaded
#       COBOL. No threads, no asyncio, no multiprocessing, no connection
#       pooling.
#
#   any third-party date library - python-dateutil, arrow, pendulum, babel
#   and every equivalent
#       acas_posting/dates.py reproduces common/maps04.cbl exactly: a
#       1600-12-31 ordinal epoch, a six-part rejection test, and the defect
#       that a rejected date leaves the caller's output field UNCHANGED
#       rather than zeroed. A general-purpose date library would be MORE
#       CORRECT THAN THE SPECIFICATION, which is the one outcome to avoid -
#       a defect reproduced is correct, a defect fixed is a failure. The
#       standard library alone is used.
#
#   any COBOL binding, FFI bridge or compiler wrapper - packages wrapping
#   cobmysqlapi.o, anything requiring cobc or a GnuCOBOL runtime, and any
#   ctypes/cffi shim onto the COBOL modules
#       No COBOL at runtime. The COBOL is the specification for this
#       migration, not a runtime dependency of its result: the shipped
#       artifact must run on a host with no COBOL compiler and no COBOL
#       runtime present. The compiled oracle lives under harness/, a SIBLING
#       of acas_posting/ that is excluded from packaging and reachable only
#       out-of-process, from the scenario and determinism suites.
# ---------------------------------------------------------------------------

# ---------------------------------------------------------------------------
# Load-bearing standard-library modules
#
# Named because substituting any of them would change behaviour, and because
# their sufficiency is the reason this dependency list is as short as it is:
#
#   decimal      every monetary and quantity computation, with the
#                precision, scale, truncation direction and sign of the
#                receiving PIC / COMP-3 field. Truncation toward zero is the
#                default; half-up rounding occurs only at the five ROUNDED
#                sites in the entire in-scope cycle.
#   datetime     the ordinal conversions underpinning acas_posting/dates.py;
#                the 1600-12-31 epoch of common/maps04.cbl round-trips
#                exactly.
#   dataclasses  the record layouts under acas_posting/records/, field for
#                field from the copybooks with nothing added.
#   argparse     the CLI batch entry points under acas_posting/cli/, which
#                bind the same logical inputs the COBOL LINKAGE SECTIONs
#                declare.
#   pathlib      file location for the generated data dictionary and the
#                harness table dumps.
#   csv          tabular dump and normalisation output.
#   json         data_dictionary/acas_posting_dictionary.json and its schema.
# ---------------------------------------------------------------------------
