# ACAS -- COBOL to Python 3.12 migration of the batch posting cycle.
# THE COMPLETE PINNED DEPENDENCY SET, in ONE manifest, hash-verified.
#
#     pip install --require-hashes -r requirements.txt
#
# WHY ONE FILE. Agent Action Plan section 0.2.1.2 names exactly two dependency
# artifacts -- `pyproject.toml` and `requirements.txt` -- with no wildcard, and
# section 0.5.1 states the dependency inventory as ONE table covering all five
# named packages: mysql-connector-python, SQLAlchemy, pytest, pytest-cov and
# PyYAML. Splitting it into three (`requirements.txt`, `requirements-harness.txt`,
# `requirements-dev.txt`) would add two manifests the plan does not name, so the whole
# inventory is consolidated here, byte-for-byte on every pin and every hash. The SECTIONS below
# preserve what the split expressed -- which set a distribution belongs to -- as
# structure inside one file rather than as three files, so `pyproject.toml`'s
# optional-dependency groups still have a one-to-one reading here.
#
# Every requirement carries a --hash for every artifact of its pinned version
# that CPython 3.12 can install, read from the package index metadata rather than
# transcribed by hand, so a substituted index cannot serve different bytes under
# the same version number. A version here that differs from `pyproject.toml` is a
# defect.
#
# DO NOT UPGRADE, downgrade or "check for newer". A driver or runtime change can
# move a stored penny, and the only acceptable proof of equivalence is an empty
# scenario diff against the compiled COBOL oracle.
#
# WHAT MUST NEVER BE ADDED, and each exclusion is a rule rather than a taste:
#   * pandas / numpy   -- they compute in binary floating point (R-2).
#   * any ORM entity layer, Alembic or other migration tool -- the schema is
#     frozen and no DDL is emitted (R-3). There is no declarative metadata of any
#     kind: nothing in the package models the schema as objects, so nothing in it
#     could generate schema even by accident.
#   * pytest-xdist or any randomising plugin -- execution is strictly sequential
#     and the scenario tier asserts on ordered state (R-3).
#   * any COBOL runtime binding -- the shipped package contains none (R-1).
